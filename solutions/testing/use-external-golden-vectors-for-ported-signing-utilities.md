# Use external golden vectors for ported signing utilities

## Context
When a service ports a signing, hashing, encryption, canonicalization, or header-building utility from another repository instead of depending on the original library, tests must protect the contract with the original implementation. This especially matters for HMAC signatures because small differences in canonical host, path, timestamp, scope, or percent encoding produce valid-looking but rejected signatures.

## Wrong Direction
Testing a Spring wrapper by comparing its output with the same local helper it delegates to is only a delegation/config binding test. If the helper is wrong, both actual and expected values are wrong in the same way and the test still passes. A hard-coded signature value is also weak if it was generated from the newly ported implementation rather than independently from the reference library or protocol document.

## Correct Pattern
Keep two layers of tests:

- A wrapper test that verifies configuration properties are passed into the signing helper.
- Contract tests with golden vectors generated by the reference implementation or protocol documentation, including the canonical string-to-sign and final headers.

For URL convenience APIs, also test the boundary conversion explicitly: URL or HTTP client request to host, raw path, optional canonicalization, scope, and emitted headers.

## Reusable Insight
For ported crypto/signature utilities, "expected = localHelper(...)" is a tautology. The expected value must come from an independent oracle, and tests should expose intermediate canonical data where possible.

## Detection
Look for tests where expected values are produced by the same production helper under test, or where service tests assert only data-class equality against another local call. Also look for missing assertions on string-to-sign, scope header presence, raw path percent-encoding, empty/root path handling, and query exclusion.

## Verification
Run the reference implementation with fixed credentials, fixed clock, and representative request inputs. Record the golden string-to-sign, signature hex, authorization header, timestamp, and optional scope header in tests. Then run the ported implementation against the same vectors and ensure focused tests fail if any canonicalization step is intentionally perturbed.
